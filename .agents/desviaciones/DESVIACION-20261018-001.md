## Qué se esperaba

`DOCTRINA_ESCRITORIO.md` §4.1: antes de entregar se ejecuta `npm run check:atomic`
y no se omite, debilita ni elude.

## Qué se observó

`npm run check:atomic` (en `pdf-tool/frontend`) termina con fallos. Primer mensaje:
`La fuente Atomic disponible está en 8cd3212ddf04e68b871f974d0f3680940ccbca66, pero atomicRef fija 67297145e2cb4bfe9ab349c471da5c3719fd1207.`
Además: huella de fuentes distinta, artefactos de gobierno
(`docs/ATOMIC_GOVERNANCE.md`, `scripts/check-atomic-provenance.mjs`) modificados
respecto a Atomic, `modal.service.ts` y `popup.service.ts` (declarados `exact`)
divergentes, y decenas de componentes con «Fuente Atomic cambió respecto al
snapshot» / «Propagación exacta divergente» (atoms avatar, badge, breadcrumb,
button, checkbox, chip, divider, file-input, floating-input, form-error,
form-input, form-row, icon-button, ...). La deriva es mayor que los 6 commits
recientes de `src/app/shared/ui`: el consumidor está atrasado respecto a toda la
política de gobierno vigente.

## Evidencia

```powershell
cd C:\Users\cotaha\source\repos\pdf-tool\frontend
npm run check:atomic
git -C ..\..\-Atomic-UI log --oneline -8 -- src/app/shared/ui
git -C ..\..\-Atomic-UI status --short
```

Salida relevante: HEAD de `-Atomic-UI` = `8cd3212`; `status` muestra `AGENTS.md`,
`CHANGELOG.md`, `LESSONS_LEARNED.md`, `docs/CONTINUIDAD_AGENTES.md` modificados y
`.agent/` sin rastrear (trabajo ajeno); el sondeo del ecosistema lo marca
`[congelado]`.

## Corrección mínima que preserva la doctrina

1. Con autorización del dueño y `-Atomic-UI` confirmado (sin cambios ajenos
   pendientes), ejecutar la propagación canónica de Atomic hacia
   `pdf-tool/frontend/src/app/shared/ui`, `docs/` y `scripts/` de gobierno
   (artefactos listados en `governanceArtifacts` del manifiesto).
2. Regenerar `docs/atomic-provenance.json` con la herramienta del flujo canónico
   (no a mano): `atomicRef` = HEAD confirmado de Atomic.
3. Reejecutar `npm run check` completo y registrar el nuevo par
   `atomicRef`/HEAD en el roadmap `PDFTOOL-20261018-001`.

## Lo que NO se debe hacer

- No editar `atomicRef` ni los SHA-256 del manifiesto a mano para «poner en verde».
- No debilitar ni saltar `check:atomic` (ni quitarlo de `npm run check`).
- No tocar `-Atomic-UI` (tiene cambios ajenos sin confirmar y está congelado).
- No copiar a ciegas ficheros de Atomic al consumidor sin el flujo gobernado: los
  componentes `adapted` tienen adaptaciones locales con registro de decisión.

## Escalado

Requiere decisión del dueño: (a) cuándo se descongela/confirma `-Atomic-UI` y
(b) autorizar la resincronización de pdf-tool. Hasta entonces `check:atomic`
permanece rojo y el resto de compuertas del frontend se ejecutan por separado.

Se clonó `-Atomic-UI` (solo lectura sobre el original) en un directorio temporal y se dejó en `67297145e2cb4bfe9ab349c471da5c3719fd1207`, el `atomicRef` vigente del manifiesto.
- Con `ATOMIC_UI_ROOT` apuntando a ese clon, `npm run check:atomic` termina en 0 («política 1.2.2, 65 componentes y 5 servicios … cero violaciones») y `npm run check` completo termina en 0 (270 pruebas, compilación correcta). No se editó el manifiesto ni se debilitó la puerta.

- Sigue abierta la migración del consumidor a `8cd3212` o posterior: exige que `-Atomic-UI` quede confirmado y una propagación gobernada con revisión de los componentes `adapted`. No se intentó en esta unidad.
